# Zunara — Search-Console-Driven Growth Loop

**Status:** process ready, awaiting data · **Created:** 2026-09-13

## Principle

> **Evidence before optimization.**

The engineering/build foundation is frozen. From here, Zunara changes through a small, measurable, approved loop — not broad rewrites. We do **not** assume a page needs work; Search Console tells us which pages and queries actually have opportunity.

## Current state (verified 2026-09-13 — read this before acting)

- **Google Search Console is NOT connected in the codebase.** There is no `google-site-verification` meta tag and no GSC integration in `src/`. So there is **no in-project GSC data**, and none should be quoted or assumed until the property is verified and data is exported.
- **The sitemap exists** at `/sitemap.xml` (generated by `src/app/sitemap.ts`) and `robots.txt` links it — good; that's what GSC needs to discover pages.
- **No web analytics is instrumented.** There is no GA/gtag/Plausible/etc. in the code, so there is currently **no on-site behavior, retention, or "Your Sky usage" data**. (The privacy policy at `/privacy` mentions "anonymised web analytics" — that is not currently implemented; see "Observed, not fixed" below.) Behavior/retention metrics require a separate, privacy-friendly analytics decision — out of scope for this pass.

**Do not fabricate, estimate, or simulate impressions, clicks, positions, or indexing counts.** If a number is not exported from the real GSC property, it does not go in the backlog.

## What data we will collect

### Search performance (GSC → Performance report)
- Query · Impressions · Clicks · CTR · Average position
- Page (URL) · Impressions · Clicks · CTR · Average position
- The Query × Page pairing (which query brings impressions to which URL)

### Indexing / technical (GSC → Pages / Sitemaps / Enhancements)
- Indexed vs not-indexed page counts
- Reason for each "not indexed" bucket (crawled-not-indexed, discovered-not-indexed, duplicate/canonical, excluded, etc.)
- Sitemap submission status + last read
- Core Web Vitals (field data) and any structured-data / mobile-usability errors

### Behavior / retention (requires analytics — NOT yet available)
- Landing page → next page, return visits, Your Sky re-use. Deferred until privacy-friendly analytics is added and approved.

## How to obtain the data

1. **Verify the property** in Google Search Console for `https://zunara.vercel.app` (URL-prefix property via the HTML-tag or DNS method; a domain property needs DNS). *If the HTML-tag method is chosen, that is a small, approved code change — a `verification.google` entry in the root `metadata` — do not add it speculatively.*
2. **Submit the sitemap** (`/sitemap.xml`) in GSC.
3. Let it accumulate (meaningful query/CTR data typically needs a couple of weeks).
4. **Export** the Performance report (Queries and Pages, last 28 days once available) and the Pages/indexing report as CSV, and drop them where the backlog below can reference them.

## The loop

```text
GSC data (real export)
   ↓
Find pages/queries with opportunity
   ↓
Prioritize (model below)
   ↓
Make ONE bounded improvement
   ↓
Deploy only after approval
   ↓
Measure again (same query/page)
   ↓
Keep / revert / iterate
```

One change at a time, scoped to a specific page or a small cluster, so the before/after in GSC is attributable.

## Opportunity patterns (how to read the export)

| Signal | Likely opportunity | Bounded action |
| --- | --- | --- |
| High impressions + low CTR | Title/meta/snippet not compelling for the query | Rewrite title/description only; re-measure CTR |
| High impressions + position ~4–15 | On-page content/relevance gap | Improve that one page's on-page content/intent match |
| Good position + poor clicks | SERP presentation / intent mismatch | Inspect the SERP; adjust snippet or add the missing answer |
| Almost no impressions | Maybe no search demand — **do not auto-rewrite** | First check whether the query has demand at all; only then act |
| Not indexed | Crawl/canonical/quality issue | Diagnose the specific "not indexed" reason before any content work |

This is exactly how the **deferred content-sameness work** (the templated 12 sign / 12 house / 10 planet pages) gets prioritized: improve the ones GSC shows are drawing impressions at position 4–15 first, rather than rewriting all 34 blind.

## Cadence

- **Weekly:** skim GSC Performance; refresh the backlog's top few rows from the latest export.
- **Per change:** one bounded improvement → approval → deploy → tag the date → re-measure the same query/page after ~2–4 weeks → keep or revert.
- Prefer title/meta experiments first (fast signal, low risk) before content rewrites.
